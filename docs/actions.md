# 小熊猫生命感动作系统（V2）

本文档对应当前 `main/auto_run.cc` 和 `main/audio.cc`。V2 已由“头尾固定正弦循环”改为“一次性行为片段 + 洗牌防重复 + 音频实时调制”。

## 1. 舵机对应关系

以下关系以本工程 README、原动作文档和实际驱动代码的共同定义为准：

| 舵机 | GPIO | 0° | 90° | 180° | 上电默认 |
|---|---:|---|---|---|---:|
| Head 头部 | IO18 | 最右 | 正前 | 最左 | 90° |
| Tail LR 尾巴左右 | IO15 | 最左 | 正中 | 最右 | 90° |
| Tail UD 尾巴上下 | IO16 | 最上 | 中间 | 最下 | 180° |

上电默认姿态为 `(Head=90, Tail LR=90, Tail UD=180)`。自动动作启动后会柔和过渡到尾巴略微抬起的生命姿态，而不是长期贴在最下面。

软件最终保护范围：

- 头部：8°～172°
- 尾巴左右：6°～174°
- 尾巴上下：10°～178°

这保留了很大的展示幅度，同时避免持续顶住机械端点。

## 2. 设计原则

### 一次性动作，不做无限循环

每个动作都有“注意—发展—收势”，结束时头部缓慢回到 90°正前。尾巴根据情绪回到低、中或略抬姿态，不强制每次回到同一个高度。

### 尾巴是主要情绪器官

尾巴同时利用 LR 和 UD 两轴，包含：

- 下垂位置的大范围左右扫动
- 从低位缓慢抬到高位
- 中高位画圆
- 上、下交错的 8 字轨迹
- 高位展示后自然放下
- 左右移动过程中持续改变高度

动作既会跨过左右中位 90°，也会覆盖上、中、下多个高度，不会一直偏在一侧或一直翘满。

### 头尾错峰

发现声音时头部先转向，尾巴延迟约 160～320ms 才回应。关键帧中也故意安排“头先看、尾后抬”或“尾先扫、头再追视”，避免三个舵机同时起停。

### 少抖动、多停顿

关键帧使用五次缓动曲线，起点和终点的速度、加速度都为零。快速动作只用于惊喜点，绝大部分动作依靠宽幅、节奏变化和短暂停顿体现生命感。

## 3. 27 个动作片段

### 日常生命动作（4）

| 片段 | 表现 |
|---|---|
| `idle_glance` | 向一侧看、停一下，再回正前；尾巴轻微后置回应 |
| `idle_low_sweep` | 尾巴保持低位，从左跨过 90°扫到右侧再收回 |
| `idle_perk` | 先转头注意，随后尾巴明显抬高并换边 |
| `idle_circle` | 中低位完成一次宽椭圆，头部反向平衡 |

### 好奇/发现用户（3）

| 片段 | 表现 |
|---|---|
| `curious_peek` | 快速发现一侧、凝视、突然检查另一侧，尾巴随后抬起 |
| `curious_track` | 头部宽幅追视，尾巴从低到高反向跟随 |
| `curious_circle` | 头部左右确认，尾巴完成一次立体圆周 |

### 吃竹子/咀嚼（3）

本产品头部只有左右自由度，无法真正低头，因此用“左右寻找—靠近食物—换边咀嚼—抬头确认”表达进食，而不把左右转头错误描述成点头。

| 片段 | 表现 |
|---|---|
| `eat_search` | 低位尾巴放松，头部在食物左右寻找并停留 |
| `eat_chew` | 不等间隔左右换边咀嚼，尾巴低位缓慢配重 |
| `eat_look_up` | 咀嚼后忽然抬尾、转头看用户，再自然收势 |

### 幼崽回应（3）

| 片段 | 表现 |
|---|---|
| `baby_seek` | 两侧寻找声源，尾巴逐步抬高 |
| `baby_wiggle` | 较活泼的宽幅头部换向和高低交错摇尾 |
| `baby_comfort` | 长停顿、慢靠近、尾巴柔和环抱式轨迹 |

### 成年/威风展示（3）

| 片段 | 表现 |
|---|---|
| `proud_display` | 头部坚定巡视，尾巴从低位升到接近最高再展开 |
| `proud_patrol` | 左右巡场，尾巴以大幅空间轨迹维持平衡 |
| `proud_call` | 配合长叫声完成一次大弧展示，然后缓慢放下 |

### 撒娇/亲近（3）

| 片段 | 表现 |
|---|---|
| `affection_nuzzle` | 偏头靠近，尾巴从低位卷向一侧再换边 |
| `affection_shy` | 先躲开、再回看，尾巴慢慢翘起 |
| `affection_curl` | 尾巴完成柔和环绕，头部延迟跟随，类似猫式撒娇 |

### 玩耍/开心（3）

| 片段 | 表现 |
|---|---|
| `playful_wag` | 尾巴连续跨中位的大幅摇摆，同时改变高度 |
| `playful_chase` | 头部像追逐尾巴一样反向移动，尾巴完成高低追逐 |
| `playful_figure8` | 尾巴完成一次完整 8 字，头部不是同相复制 |

### 长环境声（4）

| 片段 | 表现 |
|---|---|
| `ambient_listen` | 倾听远近声源，尾巴由低至高再放松 |
| `ambient_rain` | 低位避雨感、一次抬尾舒展、再换侧收拢 |
| `ambient_scent` | 缓慢左右嗅探，尾巴反向配重 |
| `ambient_stretch` | 尾巴从接近最低缓慢抬到高位，画大弧后放下 |

长音频会把这四个场景洗牌后连续演出，而不是把同一动作循环整段音频。

### 收势动作（1）

`settle` 用于开机、声音结束和自动动作重新开启：先经过一个自然过渡姿态，再让头部回正、尾巴落到略抬的放松高度。

## 4. 音频如何实时驱动动作

`audio.cc` 在每个 240-sample PCM 块上计算双时间常数包络：

- `level`：平滑的持续响度，用于尾巴逐渐抬高和扩大慢摆
- `attack`：短时起音能量，用于发现音节或叫声的开始
- `elapsed_ms / duration_ms`：提供音频进度和总时长
- `sound_index`：用于读取 Flash TOC 中的文件名与类别

动作层的应用方式：

1. `attack` 超过阈值时，头部先产生一次 5°～16°的注意偏转。
2. 尾巴延迟 160～320ms 再回应，不和头部完全同步。
3. `level` 越大，尾巴越倾向抬高，LR 轨迹会增加最多约 18°的柔和调制。
4. 所有实时调制都有衰减和 260ms 起音冷却，不会按 PCM 快速抖动。

## 5. 新音频的自动适配

动作不再依赖“TOC 第几个文件”。Flash 中新增或重排音频后，系统按文件名语义自动分类：

| 文件名关键词 | 动作家族 |
|---|---|
| 吃竹、咀嚼、eat、chew | 进食 |
| 宝宝、嘤 | 幼崽回应 |
| 撒娇、Cat、cat、亲近 | 撒娇亲近 |
| 成年、威风 | 威风展示 |
| category=ambient | 长环境声 |

未知名字会结合音频时长分为好奇、玩耍或威风，并继续受实时 PCM 包络驱动。因此以后加入新音频，即使没有专门写死时间点，也会有基本匹配动作。

## 6. 防重复与随机性

- 每个动作家族使用独立洗牌袋：袋内所有片段都演过一次后才重新洗牌。
- 新一轮洗牌的第一个片段不会和上一轮最后一个相同。
- 每次片段以 88%～114%的随机节奏播放。
- 左右镜像受平衡器约束：连续偏同一侧两次后强制换侧。
- 收势后的首次 Idle 间隔为 1.8～4.2 秒，后续完整片段启动间隔为 4.2～9 秒，片段内部的停顿长短也不同。
- 长音频按同一情绪家族持续换片段，但不会短循环同一片段。

随机性只改变“同一种情绪怎么演”，不会破坏声音和动作的语义对应。

## 7. 与旧动作系统对比

| 项目 | 旧版 | V2 |
|---|---|---|
| 动作结构 | center/amplitude/period 无限正弦 | 27 个有限关键帧故事片段 |
| 重复控制 | 每次独立随机，可能连续抽中同一模式 | 分家族洗牌，全用完才重复 |
| 左右分布 | 随机选择可能阶段性偏一侧 | 镜像平衡器强制纠偏 |
| 头尾关系 | 多数共享周期，同时起停 | 关键帧错峰 + 音频尾巴延迟 |
| 尾巴高度 | 某模式长期固定在高位或低位 | 同一片段内跨越低、中、高 |
| 长环境声 | 2～6 秒换正弦模式，观感仍像循环 | 四个完整场景连续洗牌 |
| 音频映射 | 按不稳定的 TOC 索引 1～8 | 文件名语义 + 类别 + 时长 |
| 实时音频 | 只判断“正在播放” | PCM level/attack 实时调制 |
| 运动曲线 | 周期正弦 + 交叉淡化 | 五次缓动，起停速度与加速度为零 |
| 头部归正 | 可能停在侧面模式 | 每个完整片段末尾慢回 90° |

## 8. 实机调参

最先确认 IO16 的物理方向与本文一致：0°最上、180°最下。然后观察以下三点：

1. 尾巴在 `playful_figure8` 中是否存在拉线干涉。
2. `proud_display` 的 UD=24°是否仍有机械余量。
3. `idle_low_sweep` 的 LR=32°/154°在低位是否碰壳。

若有干涉，优先修改 `output_pose()` 的统一保护范围；若只是某个造型不自然，再调整对应关键帧。不要先改变舵机方向定义。
