# 小熊猫“活体感”动作系统 V2

## 1. 已确认的舵机对应关系

本版本以 `README.md`、`docs/actions.md`、`docs/servo_movement_guide.md` 和实际驱动代码的共同定义为准。

| 部位 | GPIO | 0° | 90° | 180° | 上电默认 |
|---|---:|---|---|---|---:|
| 头部左右 | IO18 | 最右 | 正前 | 最左 | 90° |
| 尾巴左右 | IO15 | 最左 | 正中 | 最右 | 90° |
| 尾巴上下 | IO16 | 最上 | 中间 | 最下 | 180° |

尾巴由 IO15 与 IO16 组合形成二维空间轨迹。动作输出保留机械余量：头部限制在 8°～172°，尾巴左右限制在 6°～174°，尾巴上下限制在 10°～178°，防止拉线在端点持续受力。

> `docs/system.md` 中“IO15 头部、IO16/IO17 双手”的内容属于其他产品遗留说明，不适用于本小熊猫。

## 2. 新旧动作系统对比

| 项目 | 旧版 | V2 活体感系统 |
|---|---|---|
| 动作结构 | 一条正弦曲线持续循环 | 有观察、蓄势、情绪峰值和收势的一次性短表演 |
| 重复控制 | 从模式池独立随机，可能连续抽中相似模式 | 每种性格独立洗牌，同组变体全部走过后才重新洗牌，且避免首尾同段 |
| 左右分布 | 模式中心固定，容易形成视觉偏侧 | 整个片段镜像，平衡器连续偏同侧两次后强制纠偏 |
| 头尾关系 | 同一周期持续同步 | 头先发现、尾后回应；部分关键帧固定头只动尾，或固定尾只转头 |
| 尾巴高度 | 容易长期停在底部或上翘位 | 同时包含低位扫尾、中位画圈、高位展示和从下向上的完整抬尾 |
| 长环境音 | 2～6 秒换一个周期模式，仍有明显循环感 | 4 个 6～9 秒环境场景洗牌衔接，不重复播放单一动作族 |
| 新音频适配 | 依赖 Flash TOC 固定序号 | 根据文件名语义、类别、时长自动分类，并由实时 PCM 响度和起音调制 |
| 运动速度 | 同一模式速度固定 | 每次片段随机 0.88～1.14 倍节奏，动作性格一致但细节不完全相同 |
| 动作结束 | 可能停在左/右极值 | 所有表演片段均柔和回到头部 90°正前方 |

## 3. 动作目录

### 日常生命动作

| 内部名 | 表现 |
|---|---|
| `idle_glance` | 先向一侧看，再等尾巴轻轻回应，最后正视用户 |
| `idle_low_sweep` | 尾巴保持低位，从左跨过 90°扫到右侧，再从另一高度收回 |
| `idle_perk` | 像听见细小声音：先转头，尾巴延迟从低位抬起，再缓慢放下 |
| `idle_circle` | 保留旧版画圆特色，但加入头部反向观察和完整收势 |

### 好奇回应

| 内部名 | 表现 |
|---|---|
| `curious_peek` | 快速发现用户、停顿确认、尾巴随后抬起并跨侧回应 |
| `curious_track` | 从一侧追踪到另一侧，尾巴承担身体平衡感 |
| `curious_circle` | 头部先锁定目标，尾巴随后画一圈立体圆弧 |

### 吃竹子

| 内部名 | 表现 |
|---|---|
| `eat_search` | 左右寻找竹子，尾巴保持低位但不是静止 |
| `eat_chew` | 头部不等速地左右小口咀嚼，尾巴在低位轻换重心 |
| `eat_look_up` | 吃到喜欢的食物后抬尾并做一次满足的跨侧摆动 |

头部只有左右自由度，不能真正低头，因此本动作不伪造“上下点头”，而用左右找食、偏头咀嚼与低位尾巴配合表达进食。

### 宝宝呼唤

| 内部名 | 表现 |
|---|---|
| `baby_seek` | 急切左右寻找照顾者，尾巴由低到高回应 |
| `baby_wiggle` | 幅度较大但不高频抖动的幼崽扭动 |
| `baby_comfort` | 找到用户后靠近一侧，尾巴慢慢卷高，形成被安抚感 |

### 成年鸣叫 / 威风展示

| 内部名 | 表现 |
|---|---|
| `proud_display` | 先观察，再高高抬尾，做完整左右展示 |
| `proud_patrol` | 大范围巡视，尾巴以相反方向平衡，像在巡查领地 |
| `proud_call` | 鸣叫前蓄势，声音高潮时尾巴抬至高位并画大弧线 |

### 撒娇亲近

| 内部名 | 表现 |
|---|---|
| `affection_nuzzle` | 头部向用户一侧靠近，尾巴延迟卷向同侧再慢慢松开 |
| `affection_shy` | 先躲向一侧观察，再突然靠近，尾巴从低位变成欢迎姿态 |
| `affection_curl` | 慢速猫式撒娇，尾巴从下面沿空间弧线卷高，不频繁摇摆 |

### 开心玩耍

| 内部名 | 表现 |
|---|---|
| `playful_wag` | 中低高三种高度交替的大幅跨中线摇尾 |
| `playful_chase` | 头似乎追逐尾尖，头尾方向交错而非同步复制 |
| `playful_figure8` | 保留旧版 8 字轨迹，扩大左右和上下范围并增加回正收势 |

### 长环境音场景

| 内部名 | 表现 |
|---|---|
| `ambient_listen` | 安静聆听环境，头先定位，尾巴隔一拍抬起 |
| `ambient_rain` | 像感受雨滴一样换侧观察，尾巴走一圈不规则空间路径 |
| `ambient_scent` | 低位嗅探式搜寻，再抬尾确认目标 |
| `ambient_stretch` | 从尾巴最下面开始，缓慢完成一次大幅抬尾伸展和放松 |

长音频播放期间按洗牌顺序衔接这些完整场景，不会把某一个动作无限循环。

## 4. 音频如何实时驱动动作

`audio.cc` 在 Opus 解码后的 PCM 数据上计算两种包络：

- `level`：慢速响度，控制尾巴空间轨迹的附加幅度；持续声音越明显，尾巴越有回应并略微抬高。
- `attack`：短时起音，超过阈值且通过 320ms 防抖后，先触发一次转头注意；尾巴再延迟 160～320ms 做反向回应。

PCM 数据不会直接逐点映射为舵机角度。音频只对已经设计好的动作片段进行小幅调制，因此能跟随新音频，又不会产生高频机械抖动。

### 新增音频时的自动分类

1. 类别为 `ambient`：进入长环境场景洗牌。
2. 文件名含“吃竹 / 咀嚼 / eat / chew”：进食动作。
3. 含“宝宝 / 嘤嘤 / baby”：幼崽呼唤动作。
4. 含“撒娇 / 亲近 / Cat / cat”：亲近动作。
5. 含“成年 / 威风 / adult”：威风展示动作。
6. 其余叫声结合时长选择好奇、开心或威风动作。
7. 不论属于哪类，实时 PCM 包络都会继续提供细节同步。

为了获得最准确的自动匹配，新增文件名应包含情绪或行为词，例如 `开心回应`、`警觉短叫`、`撒娇`、`吃竹子`；无法识别的名字仍会使用通用叫声动作，不会失去动画。

## 5. 随机性与防机械感

- 每个行为组使用独立洗牌袋，不放回抽取。
- 可镜像动作随机整段左右翻转；若连续偏同侧两次，平衡器会强制下一次纠偏。
- 每次动作节奏有小范围随机变化。
- 音频起音的转头方向交替，且有 320ms 冷却，避免跟着每个音节来回抖。
- 头部与尾巴使用不同的响应时机；尾巴响度调制是慢相位，不和头部同频。
- 动作之间保留约 1.8～9 秒不等的自然观察空隙，避免宠物一直忙乱。
